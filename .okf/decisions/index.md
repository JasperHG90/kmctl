# Decisions

- [ADR 0001](0001-standalone-cli-installs-its-plugin.md): kmctl is a
  standalone Typer CLI that installs its own plugin, with thin skills.
  (amended: APM installs the package and kmctl plugin patch adds the rest,
  ADR 0021)
- [ADR 0002](0002-briefing-and-rules-injected-by-the-cli.md): The CLI serves
  one briefing with state, routing and rules; the hook injects it.
  (amended: the rules moved to .claude/rules/, ADR 0011)
- [ADR 0003](0003-claude-code-plugin-first-depends-on-okf.md): The Claude Code
  plugin comes first and depends on okf@scaccogatto. (superseded by ADR 0014)
- [ADR 0004](0004-sessionstart-is-the-only-hook.md): SessionStart is the only
  hook. (superseded by ADR 0028)
- [ADR 0005](0005-audits-report-only.md): Audits report only; CI runs free
  checks on every PR and an opt-in LLM audit.
- [ADR 0006](0006-staleness-from-okf-fields.md): Staleness comes from OKF's
  own fields; a covers field is out of scope.
- [ADR 0007](0007-skills-are-made-with-skill-creator.md): Every skill is made
  with the skill-creator skill.
- [ADR 0008](0008-handoffs-are-okf-concepts.md): /handoff and /continue write
  and read handoff concepts in .okf/handoffs/.
- [ADR 0009](0009-handoff-key-extension-field.md): handoff_key is kmctl's
  one OKF extension field; I4 allows fields an ADR names.
- [ADR 0010](0010-the-ci-audit-runs-hermes-agent-against-any-openai-compatible-provider.md):
  The CI audit runs Hermes Agent with read-only kmctl tools against any
  OpenAI-compatible provider, replacing Claude Code. (superseded by ADR 0017)
- [ADR 0011: kmctl init writes knowledge rules and a CLAUDE.md block for Claude Code](0011-kmctl-init-writes-knowledge-rules-and-a-claude-md-block-for-claude-code.md): kmctl init writes four knowledge rules to .claude/rules/, a kmctl block into CLAUDE.md and AGENTS.md, and a first decision; the briefing stays the cross-harness path. (amended: APM installs the rules since ADR 0014, and the block holds six duties and starts at summary.md, and init links a page it adds to a kept index, ADR 0027, and writes the first decision only when no record exists)
- [ADR 0012: Releases come from CI](0012-releases-come-from-ci.md): A hand-run release workflow opens a version pull request and a tag workflow publishes the GitHub Release; the plugin manifest is the one version source, with no PyPI and no hatch-vcs. (amended: each package's apm.yml under packages/ is its version source, ADR 0045)
- [ADR 0013: kmctl installs through APM too](0013-kmctl-installs-through-apm-too.md): APM installs kmctl's skills, agent and hook from the apm subfolder package as a second route beside kmctl plugin install; the CLI is still installed with uv tool install. (superseded by ADR 0014)
- [ADR 0014: APM is the only install route](0014-apm-is-the-only-install-route.md): kmctl's skills, audit agent and knowledge rules ship only as kmctl's APM package (packages/kmctl/apm since ADR 0045), which kmctl plugin install --harness writes into apm.yml and installs with APM; kmctl writes the SessionStart hook and okf's MCP server itself. (amended by ADR 0020 and ADR 0021: APM installs the hooks and MCP server too, from the user's apm.yml entry, and kmctl plugin patch adds the rest)
- [ADR 0015: Antigravity gets skills and rules from APM and a kmctl plugin folder](0015-antigravity-gets-skills-and-rules-from-apm-and-a-kmctl-plugin-folder.md): kmctl plugin install --harness antigravity installs the skills and rules with APM and writes .agents/plugins/kmctl/ itself, holding the translated agents, the SessionStart hook and okf's MCP server. (amended by ADR 0020 and ADR 0021: apm install, then kmctl plugin patch for the agents)
- [ADR 0016: Antigravity rules come from the kmctl plugin folder](0016-antigravity-rules-come-from-the-kmctl-plugin-folder.md): kmctl writes its four knowledge rules for Antigravity into .agents/plugins/kmctl/rules/ in the form agy reads, and deletes the copies APM writes to .agents/rules/. (superseded by ADR 0020)
- [ADR 0017: The CI audit is a standalone PydanticAI agent script](0017-the-ci-audit-is-a-standalone-pydanticai-agent-script.md): action/agent.py, one PydanticAI script run with uv run, replaces the Hermes audit: it takes a task, a system prompt, any provider, context and skill folders, can run shell commands, and writes a typed report kept as an artifact.
- [ADR 0018: kmctl runs okf's Stop check for Antigravity](0018-kmctl-runs-okf-s-stop-check-for-antigravity.md): kmctl's plugin folder runs okf's Stop check from the repository root and in Antigravity's format, and takes APM's broken copy out of .agents/hooks.json.
- [ADR 0019: kmctl plugin remove uninstalls the package and reinstalls the harnesses kept](0019-kmctl-plugin-remove-uninstalls-the-package-and-reinstalls-the-harnesses-kept.md): kmctl plugin remove runs apm uninstall on kmctl's entry, removes the hook, MCP entry and plugin folder kmctl wrote, and installs the kept harnesses again at their ref. (superseded by ADR 0021)
- [ADR 0020: APM installs the hooks, MCP server and rules; kmctl patches the rest](0020-apm-installs-the-hooks-mcp-server-and-rules-kmctl-patches-the-rest.md): kmctl's APM package ships its SessionStart hooks, okf's MCP server and per-harness rules in sub-packages; kmctl writes only what APM cannot install yet: Antigravity agents and the fix for okf's Antigravity Stop hook.
- [ADR 0021: APM installs kmctl's package; kmctl plugin patch adds the rest](0021-apm-installs-kmctl-s-package-kmctl-plugin-patch-adds-the-rest.md): kmctl plugin install, update and remove give way to apm install, apm uninstall and kmctl plugin patch, which writes only what APM cannot install yet.
- [ADR 0022: Docs pages carry optional OKF front matter and generated folder indexes](0022-docs-pages-carry-optional-okf-front-matter-and-generated-folder-indexes.md): docs/ pages may carry the OKF fields description, stale_after, verified and sources, and each Diataxis folder gets a README.md index that kmctl check --fix generates, without docs/ becoming an OKF bundle.
- [ADR 0023: kmctl verify records a person's check](0023-kmctl-verify-records-a-person-s-check.md): kmctl verify writes the verified entry a person's check earns, so a concept or docs page leaves kmctl review due; an agent runs it only on that person's confirmation, never on an audit verdict.
- [ADR 0024: OpenCode gets the package from APM and its agents, rules and briefing from kmctl plugin patch](0024-opencode-gets-the-package-from-apm-and-its-agents-rules-and-briefing-from-kmctl-plugin-patch.md): apm install --target opencode brings the skills and okf's MCP server; kmctl plugin patch rewrites the agents into OpenCode's format and writes the rules, their instructions entry and a briefing plugin.
- [ADR 0025: The starter template lives in kmctl and shares its release tags](0025-the-starter-template-lives-in-kmctl-and-shares-its-release-tags.md): copier.yml sits at kmctl's root with the template in starter/, so each kmctl release tag is a template release, and scripts/release.py set moves kmctl_ref's default to it.
- [ADR 0026: The kmctl on PATH runs the release a project's lock pins](0026-the-kmctl-on-path-runs-the-release-a-project-s-lock-pins.md): Before any command, kmctl reads apm.lock.yaml and, when it pins another release, runs that release through uvx at the lock's commit with KMCTL_PINNED=1; the copy on PATH adds the briefing's newer-release line.
- [ADR 0027: The bundle opens with a summary that kmctl keeps in step](0027-the-bundle-opens-with-a-summary-that-kmctl-keeps-in-step.md): kmctl init writes .okf/summary.md, a page of at most 500 words that the briefing points to first; kmctl review due lists it when a concept changed in a commit after it, and kmctl summary ack, which writes the checked extension field, clears that. (amended: the summary's sections are The project, How it works, What it has settled and Where it stands, and it distils the knowledge rather than listing the decisions, and a body over 500 words is a warning that kmctl check --strict fails)
- [ADR 0028: Two hooks: the session briefing and the summary nudge](0028-two-hooks-the-session-briefing-and-the-summary-nudge.md): kmctl ships a SessionStart hook that prints the briefing and a Claude Code PostToolUse hook that runs kmctl summary nudge after Write, Edit, MultiEdit and Bash calls; neither blocks. (superseded by ADR 0029)
- [ADR 0029: The session briefing is kmctl's only hook again](0029-the-session-briefing-is-kmctl-s-only-hook-again.md): kmctl drops the PostToolUse summary nudge for every harness; the briefing, the AGENTS.md duty and kmctl review due say when the summary is behind.
- [ADR 0030: Projects commit what APM deploys](0030-projects-commit-what-apm-deploys.md): A project commits the files apm install and kmctl plugin patch deploy for its harnesses and gitignores only apm_modules/, as APM's guide says.
- [ADR 0031: A decision record may be draft until it is accepted](0031-a-decision-record-may-be-draft-until-it-is-accepted.md): A decision record may carry status draft while its choice awaits acceptance; once accepted its status becomes stable and a log.md line records it.
- [ADR 0032: kmctl review due decides by commit order](0032-kmctl-review-due-decides-by-commit-order.md): kmctl review due finds the commit that holds a file's newest verified entry and compares sources and the file itself with HEAD from there, so a squash or rebase merge keeps a verification and an edit after it makes the file due.
- [ADR 0033: kmctl check fails on a missing link target inside the bundle](0033-kmctl-check-fails-on-a-missing-link-target-inside-the-bundle.md): kmctl check reports every link in .okf/ whose target does not exist, relative or from the bundle root, as it does for docs/, instead of leaving links inside the bundle to the okf validator, which only warns.
- [ADR 0034: kmctl mv renames a concept and rewrites the links to it](0034-kmctl-mv-renames-a-concept-and-rewrites-the-links-to-it.md): kmctl mv OLD NEW renames a concept within its folder, rewrites the links to it in .okf/ and docs/, renumbers a decision title, and lists the lines elsewhere it did not rewrite.
- [ADR 0035: kmctl's repository answers and triages with Hermes](0035-kmctl-s-repository-answers-and-triages-with-hermes.md): Two workflows in kmctl's own repository run the toiminnot Hermes actions: one answers a member's /hermes comment, the other posts a triage comment of under 200 tokens and labels each new issue; the knowledge audit stays on action/agent.py.
- [ADR 0036: Claims are extracted by the agent through kmctl audit claims](0036-claims-are-extracted-by-the-agent-through-kmctl-audit-claims.md): A coding agent's own model extracts a bundle's claims through kmctl audit claims todo, submit and list, validated by one Pydantic schema into a git-ignored SQLite store at .kmctl/audit.sqlite; the CLI makes no model call.
- [ADR 0037: The claims and checks agents get a plain shell and I2 narrows](0037-the-claims-and-checks-agents-get-a-plain-shell-and-i2-narrows.md): The kmctl-claims-extractor and the later check writer get Read and a plain shell and write only through kmctl audit, held by their instructions, since Antigravity cannot limit a subagent's shell; I2 narrows to the read-only auditor and the CI audit.
- [ADR 0038: Checks are step data that kmctl reruns and only checks that notice a change are stored](0038-checks-are-step-data-that-kmctl-reruns-and-only-checks-that-notice-a-change-are-stored.md): An agent writes each claim's check as steps from a fixed DSL through kmctl audit checks; kmctl reruns them with no model when the files they read change, and submit refuses a weak check that notices none of the in-memory changes to the code it matched; code and query steps need kmctl[audit].
- [ADR 0039: kmctl audit judge asks an optional decision model, off by default](0039-kmctl-audit-judge-asks-an-optional-decision-model-off-by-default.md): kmctl audit judge failure|claim|link asks a configured decision model (Jev or Clef) one question about stored checks or a claim by id, caches the answer in the store, and is the one model call kmctl makes: off by default, a provider and model per question, settings in a per-user audit.toml.
- [ADR 0040: The audit pipeline holds its agents by a hook and keeps answers through rewording](0040-the-audit-pipeline-holds-its-agents-by-a-hook-and-keeps-answers-through-rewording.md): After the first full kmctl audit run: a kmctl audit guard PreToolUse hook holds the Claude Code agents to kmctl audit commands, answers follow a reworded claim of the same sentence, reasons go stale only on files their anchors name, checks read markdown outside the knowledge, and a YAML key rename is a mutation.
- [ADR 0041: People review claims and checks on a local page, and their feedback goes back to the agents](0041-people-review-claims-and-checks-on-a-local-page-and-their-feedback-goes-back-to-the-agents.md): kmctl audit ui serves a page on 127.0.0.1 where a person gives a claim or its check a thumbs up or down and a note, says whether the claim holds, and asks the decision model for a second opinion; a thumbs down or a verdict the check disagrees with puts the work back in todo with the note until the agent's next answer.
- [ADR 0042: Code coverage counts the lines a check matched](0042-code-coverage-counts-the-lines-a-check-matched.md): Each check step records the lines it matched, and kmctl audit coverage and the code view of kmctl audit ui count a line of code as covered when a stored check matched it on its last run.
- [ADR 0043: The audit is its own library, kmaudit, served over MCP](0043-the-audit-is-its-own-library-kmaudit-served-over-mcp.md): The audit leaves kmctl for kmaudit, a separate package in packages/kmaudit/ of this repository that runs without kmctl on any folder of markdown docs; kmctl stays at the root, and kmaudit's main interface becomes a stdio MCP server.
- [ADR 0044: kmctl and kmaudit are both workspace packages](0044-kmctl-and-kmaudit-are-both-workspace-packages.md): kmctl moves from the repository root to packages/kmctl beside kmaudit, the root becomes a uv workspace that installs nothing, and releases after v0.12.2 install from #subdirectory=packages/kmctl.
- [ADR 0045: Each package keeps its APM package and version](0045-each-package-keeps-its-apm-package-and-version.md): kmctl's APM package moves from apm/ to packages/kmctl/apm, kmaudit gets one in packages/kmaudit/apm whose apm.yml carries its version in place of a VERSION file, and releases after v0.12.2 are added with path: packages/kmctl/apm.
- [ADR 0046: kmctl works from code toward knowledge and kmaudit from knowledge toward code](0046-kmctl-works-from-code-toward-knowledge-and-kmaudit-from-knowledge-toward-code.md): A feature goes in the package whose direction it shares: kmctl starts from the code and the decisions and keeps docs/ and .okf/ current, kmaudit starts from docs/ and .okf/ and checks them against the code.
- [ADR 0047: Unrecorded decisions are listed by kmctl and judged by a skill that only reports](0047-unrecorded-decisions-are-listed-by-kmctl-and-judged-by-a-skill-that-only-reports.md): kmctl decision candidates lists, with no model, the changes since the newest decision record; the decision-gaps skill judges every one and reports the changes that made a decision no record covers; the user decides which become records.
- [ADR 0048: kmctl summary ack writes one file per ack, so branches merge without a conflict](0048-kmctl-summary-ack-writes-one-file-per-ack-so-branches-merge-without-a-conflict.md): kmctl summary ack writes a file with its own name under .okf/.acks/ and no longer the checked block in the summary, which every ack rewrote, so two branches that both acked always conflicted.
- [ADR 0049: The log records lifecycle events only](0049-the-log-records-lifecycle-events-only.md): kmctl and its rules write a line to .okf/log.md only when a concept is created, renamed, superseded, deprecated, removed, accepted or verified, not when it is edited.
